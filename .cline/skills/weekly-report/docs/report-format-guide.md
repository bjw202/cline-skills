# 주간회의 보고서 형식 가이드

주간회의 보고서의 공식 형식과 작성 규칙을 정의합니다.

---

## 1. 전체 구조

```
## [기간] 주간회의 보고

### 진행내용

1. [업무 항목명]
   - 세부 내용
   - 세부 내용
   .. 참고사항/보충 설명
   ** 관련 부서 의견

### 리스크

- 리스크 항목

### 향후계획

- 계획 항목 (~날짜)
```

---

## 2. 섹션별 작성 규칙

### 진행내용 섹션

**번호 매기기:** 업무 항목마다 1, 2, 3... 번호를 부여합니다.

**들여쓰기 규칙:**
| 기호 | 의미 | 예시 |
| --- | --- | --- |
| `-` (하이픈) | 세부 진행 내용 | `- 금속 소재 레이저 용접 가능성 검증 완료` |
| `..` (점 두 개) | 참고사항, 보충 설명, 현재 이슈 | `.. 4축 레이저 설비 확보 어려워 대안 검토중` |
| `**` (별표 두 개) | 관련 부서 의견, 외부 피드백 | `** 사업부: 최종 형상 빠른 시일 내 제작 필요` |

**작성 지침:**
- 각 업무 항목은 명확한 제목으로 시작합니다 (프로젝트명 + 작업 내용)
- 세부 내용은 완료된 것과 진행 중인 것을 구분하여 작성합니다
- 참고사항(`..`)은 제약사항, 미결 이슈, 추가 검증 필요 항목을 기재합니다
- 부서 의견(`**`)은 회의에서 나온 타 부서/팀의 피드백을 기재합니다

### 리스크 섹션

**작성 지침:**
- 현재 진행에 영향을 주는 위험 요소를 기재합니다
- 일정 차질, 의존성 이슈, 기술적 불확실성 등을 포함합니다
- 리스크가 없으면 `- 해당 없음`으로 작성합니다

**리스크 작성 패턴:**
```
- [원인]으로 인한 [결과] 우려
- 예: 의사결정 지연으로 양산 일정 차질 우려
- 예: 공급사 납기 지연으로 3/30 마일스톤 위험
```

### 향후계획 섹션

**작성 지침:**
- 다음 보고 기간까지 완료해야 할 항목을 기재합니다
- 반드시 완료 예정일을 포함합니다: `~날짜` 형식 사용
- 중요도 순 또는 일정 순으로 정렬합니다

**일정 표기 형식:**
```
- 형상 구동 가능 여부 확인 (~3/20)
- 금형 제작 완료 및 타발 (~3/30)
- 2분기 계획 수립 (~4/4)
```

## 3. 완성 예시

아래는 입력 메모를 변환한 완성 예시입니다.

**입력 메모 (원본):**
```
Ring2 배터리 캔 레이저 용접 공정 검토
- 금속 소재 레이저 용접 공정 가능성 검증 완료
- 비드폭 0.1 이하 구현을 위한 광학 사양 및 공정 조건 확보
4축 레이저 설비 확보가 어려워 분할 용접 공법 검토중
분할 용접시 중첩부 크랙 없음 (추가 검증 필요)
사업부 의견: 최종 형상 제작 빠른 시일 내 필요

리스크: 의사결정 지연으로 양산 일정 차질
계획: 형상 구동 확인 ~3/20, 금형 제작 ~3/30
```

**변환 결과:**
```markdown
## 2025년 3월 10일~14일 주간회의 보고

### 진행내용

1. Ring2 배터리 캔 레이저 용접 공정 검토
   - 금속 소재 레이저 용접 공정 가능성 검증 완료
   - 비드폭 0.1 이하 구현을 위한 광학 사양 및 공정 조건 확보
   - 3D 목업 샘플 대응을 위한 광학사양 및 공정 조건 확보
   .. 4축 레이저 설비 확보 어려워, 유효 범위 내 분할 용접 공법 대안으로 검토중
   .. 분할 용접 시 중첩부 크랙 및 외관 품질 특이점 없음 (추가 검증 필요)
   ** 사업부: 최종 형상 빠른 시일 내 제작 필요

2. 3D 목업 샘플 대응 용접 공법 검토
   - 1안: 다관절 로봇 + 회전축 레이저 설비 활용 용접 공법
   - 2안: 3차원 스캐너 활용

### 리스크

- 의사결정 지연으로 양산 일정 차질 우려

### 향후계획

- 형상 구동 가능 여부 확인 (~3/20)
- 금형 제작 완료 및 타발 (~3/30)
```

## 4. 메모 → 보고서 변환 원칙

| 원칙 | 설명 |
| --- | --- |
| 구조화 | 두서없는 내용을 3개 섹션(진행/리스크/계획)으로 분류 |
| 계층화 | 업무 항목 > 세부내용 > 참고사항 > 부서의견 순으로 들여쓰기 |
| 완성도 | 누락된 정보는 사용자에게 질문하여 보완 |
| 간결성 | 중복 표현 제거, 핵심 내용만 남김 |
| 일관성 | 같은 업무 단위는 하나의 번호 항목으로 묶음 |

---

## 5. 자주 묻는 질문

**Q. 진행내용이 하나밖에 없으면?**
번호를 붙이되 `1.` 항목 하나만 작성합니다.

**Q. 부서 의견이 없으면?**
`**` 줄은 생략합니다. 있는 항목만 포함합니다.

**Q. 향후계획 날짜를 모르면?**
`ask_followup_question 도구를 사용하여 질문합니다:` "향후계획 항목의 완료 예정일을 알려주세요."

**Q. 업무 항목이 여러 팀에 걸쳐 있으면?**
팀/프로젝트 단위로 묶어서 번호 항목을 구성합니다.
