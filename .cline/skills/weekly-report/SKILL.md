## 핵심 절차

### Step 1: 입력 수집

**1a. 텍스트로 입력된 경우**:사용자가 메시지에 직접 붙여넣은 메모를 그대로 사용합니다.

**1b. 파일 경로로 입력된 경우:**`read_file 도구로 해당 경로의 파일을 읽습니다.`

### Step 2: 내용 분석

입력 메모를 분석하여 아래 4개 항목의 충족 여부를 확인합니다:

| 항목 | 확인 내용 |
| --- | --- |
| 진행내용 | 업무 항목별 세부 내용, 참고사항, 관련 부서 의견 |
| 리스크 | 현재 또는 잠재적 위험/장애요소 |
| 향후계획 | 일정이 포함된 다음 단계 |
| 기간 | 이번 주 기간 (예: 3/10\~3/14) |

### Step 3: 부족한 정보 질문

분석 후 누락된 항목이 있으면 `ask_followup_question 도구를 사용하여 질문합니다:`

질문 예시 패턴:

- 리스크 미기재: "리스크 항목이 없습니다. 현재 프로젝트에서 우려되는 리스크가 있나요? (없으면 '없음'이라고 답해주세요)"
- 향후계획 일정 없음: "향후계획에 일정이 없습니다. 각 항목의 완료 예정일을 알려주세요."
- 기간 미기재: "보고서에 들어갈 주간 기간을 알려주세요. (예: 2025년 3월 10일\~14일)"
- 진행내용 불명확: "'{항목명}'의 진행 상태를 좀 더 구체적으로 설명해 주시겠어요? (완료/진행중/검토중)"

**최대 3번까지만 질문합니다.** 누락 항목이 많으면 한 번에 묶어서 질문합니다.

### Step 4: 보고서 생성

`docs/report-format-guide.md`의 형식을 따라 보고서를 작성합니다.

형식 요약:

```
## [주간 기간] 주간회의 보고

### 진행내용
1. [업무 항목명]
   - 세부 내용
   .. 참고사항 (선택)
   ** 관련 부서 의견 (선택)

### 리스크
- 리스크 항목

### 향후계획
- 계획 항목 (~날짜)
```

### Step 5: 파일 저장

`write_to_file 도구로 reports/주간보고_YYYY-MM-DD.md 파일을 생성합니다.`

- 날짜는 보고서 작성 기준 날짜(금요일 또는 해당 주 마지막 업무일) 사용
- 파일이 이미 존재하면 `ask_followup_question 도구를 사용하여 질문합니다:` "같은 날짜의 파일이 이미 있습니다. 덮어쓸까요, 아니면 다른 이름으로 저장할까요?"
